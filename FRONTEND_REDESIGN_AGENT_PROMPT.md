## Ground truth: what this product actually is

**Ledger** — internal decision console for fraud analysts/compliance staff
at a payments company, used for hours, for high-stakes APPROVE/REVIEW/
DECLINE calls that must be auditable. Register: precise, calm, numerate —
a financial instrument, not a "threat monitoring" sci-fi panel.

The real backend this UI serves (from `api/main.py`, `api/schemas.py`,
`api/store.py` — read these for exact field names before touching
components):
- Policy v1 (static thresholds `review_above`/`decline_above`) coexisting
  with policy v2 (`bandit_policy.py`, LinUCB), switchable via
  `FRAUD_BANDIT_ENABLED`. Every decision carries `policy_version`,
  `reason_code`, `auto_actioned`, `audit_sampled` (bias-check samples).
- SHAP-grounded `Driver[]` (feature, label, value_text, typical_text,
  contribution, direction) on every explained decision — never invented.
- LLM audit reports (`audit_report.py`) with a hard-coded
  `"Generated by AI — subject to human review."` footer and a `source:
  "llm"|"template"` tag — both must always be visibly shown, never
  suppressed or de-emphasized.
- A real appeal/reversal endpoint (`POST /api/review/{id}/appeal`) and a
  bandit promotion gate (`POST /api/bandit/promote`, IPS-evaluated,
  mirrors the model retrain gate) — these are real, interesting system
  events; give them real screen space instead of decorative charts.
- `metrics_summary`, `metrics_timeseries`, `metrics_dispositions`,
  `metrics_loss`, `metrics_rules` endpoints — use these exact field names
  when wiring new components, don't invent parallel ones.

Delete entirely: `--accent-teal*`, `--accent-cyan`, `--accent-sky`,
`@keyframes pulseGlow`, `.glass-panel` (`backdrop-filter`/blur/shadow),
`.glass-panel-hover` (glow border + lift), `.animate-row-flash`'s teal-glow
keyframe.

Replace with flat, functional equivalents:

```css
.panel {
  background-color: var(--surface-1);
  border: 1px solid var(--border-subtle);
  border-radius: 4px;
  /* no shadow, no blur */
}

.panel-hover {
  transition: background-color 0.15s ease, border-color 0.15s ease;
}
.panel-hover:hover {
  background-color: var(--surface-hover);
  border-color: var(--border-muted);
  /* no glow, no transform/lift */
}

@keyframes rowSettle {
  from { background-color: var(--surface-hover); }
  to   { background-color: transparent; }
}
.animate-row-flash {
  animation: rowSettle 0.6s ease-out forwards;
  /* was a 1.2s teal pulseGlow flash — now a brief, quiet settle using the
     neutral hover surface, not a signal color; new rows shouldn't look
     like an alert */
}
```

Keep `fadeIn`/`slideInRight` if used for real state transitions (panel
open/close), but drop `pulseGlow` — nothing in this UI should idle-pulse.

## Step 2 — New rules to encode as reusable components

1. **Score-with-driver component** (new: `components/ui/ScoreBar.tsx`) —
   the product's signature element. Props: `probability: number`,
   `topDriver?: { label: string; direction: "fraud" | "safe" }`,
   `thresholds?: { review_above?: number; decline_above?: number;
   auto_action_above?: number }`. Renders: a horizontal 0–1 track with tick
   marks at any provided thresholds, a filled bar to `probability`, the
   exact number in `.font-mono` at the end, and — if `topDriver` present —
   `· {label} ↑` (↑ for fraud-direction, ↓ for safe-direction) inline
   after the number, in `--text-secondary`. **Never** a radial/gauge/dial
   SVG anywhere — grep the codebase for any existing gauge/dial component
   (the "Threshold Optimizer" gauge visible in the current screenshots)
   and replace it with this component.
2. **Decision tag** — text label colored by `--status-approve/review/block`
   (text color only, on a neutral `--surface-2` background at low opacity
   via the `-soft` tokens) — not a filled glowing pill.
3. **Audit-sampled indicator** — a small icon + "Audit sample" label,
   distinct from the decision tag, for any row where `audit_sampled=true`
   from the bandit event — this is operationally different from a normal
   review-tier route (it's a bias-check on the auto-decline policy) and
   must be visually distinguishable, not folded into the same tag.
4. **AI-disclaimer block** — a fixed, always-visible component wrapping any
   LLM-narrated content (`audit_report.py` output): renders the
   `ai_disclaimer` text verbatim plus a `source: llm | template` tag.
   Never collapsible, never a tooltip-only footnote.
